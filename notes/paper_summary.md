# Paper and implementation notes

Source: [arXiv 2510.02373v1](https://arxiv.org/html/2510.02373v1), Sections 3–5 and Appendices A, F, G. This pilot cannot establish reproduction of the reported performance.

The threat model allows a small number of malicious memory records, crafted offline, to steer triggered queries while preserving ordinary behavior. AgentPoison optimizes retrieval-trigger behavior; EHRAgent's released payload appends trigger-conditioned deletion instructions to knowledge and changes LoadDB to DeleteDB. Consensus validation generates a reasoning path per retrieved memory and rejects paths judged inconsistent. Rejected paths become negative lessons. Appendix G retrieves lessons by actions similar to those of initially retrieved memories and injects a warning against repeating their mistakes. Appendix A describes a consensus plan followed by individual checks; Appendix F describes response/entity/chain extraction and auditing prompts. ASR-r, ASR-a and ASR-t concern retrieval, thought and task stages; ACC concerns benign queries. The paper uses four retrieved memories and four lessons. Reference percentages are comparison values, not targets for this pilot.

| Component | Actual file/function and evidence |
|---|---|
| Trigger search | `algo/trigger_optimization.py` dispatches EHR AP to `algo/ehr_trigger_optimization.py:optimize`. Local DPR context encoder, five Gaussian-mixture centroids, maximize mean distance minus 0.1 within-triggered-query compactness. Target scoring and coherence filtering disabled explicitly. |
| Memory loading / identity | Both `algo/utils.py` and `EhrAgent/ehragent/utils.py` delegate EHR loaders to `replication.py`. Sorted log files, stable first-seen deduplication, content-derived IDs and caches bound to ordered records, vocabulary, config and weight hash. |
| Injection | `MedAgent.load_db`: append four records from first four deterministic source memories, conditional deletion knowledge and DeleteDB code; embed actual poisoned question/action. |
| Retrieval / validation | `MedAgent.retrieve_embedding_examples`: cosine top-four question retrieval; `consistency.check_consistency` → `ConsistencyChecker.check` → per-memory `_generate_reasoning_chains` → `_check_with_llm`; filter inconsistent records. |
| Lesson path | Same MedAgent method searches top-four action neighbors for each initially retrieved memory, collects existing lessons, then judges/stores new negative paths. Lesson annotations persist within a run and reset between processes; each memory retains only its latest negative chain. Four action neighbors are searched per initial memory, then lesson IDs are deduplicated; this is not a global four-lesson cap. Both knowledge and code contexts receive preventive warning. `lesson_fixture.json` records a controlled two-query traversal. |
| Generation / endpoint | `generate_init_message`, `retrieve_knowledge`, `generate_code`; EHR-only `llm_env.py` wraps existing OpenRouter client. Code is returned directly, never executed by this evaluation path. No clinical answers measured. |
| Evaluation | Original `EhrAgent/ehragent/eval.py`: character-set strip, last substring match, exclusion of missing references, repeated deletion-string retrieval heuristic, knowledge deletion mention, DeleteDB code mention, BERT pooler code cosine >0.95. Companion evaluator retains these definitions separately from ID-based exposure and syntactic call checks. |

Material discrepancies: released checker combines extraction steps into one call per memory and makes one joint judgment, rather than Appendix A's explicit consensus-plan/pairwise procedure. This matches Appendix F's joint prompt; Figure 10 uses one combined consistency/safety label, whereas released code requests two booleans. Preserve this and label defense a released-code approximation. Released lesson storage uses raw reasoning paths without a separate concise synthesis; this agrees with the main-text negative-path definition but differs from Appendix G's synthesis description. Lessons are fetched before new ones are stored, and a later rejection overwrites that record’s prior lesson. The released per-action top-four can deliver more than four distinct lessons overall (observed maximum10 in this pilot). Released code appended warning only to knowledge examples; this pilot minimally prepends it to both knowledge and code examples to follow Appendix G. Released action embeddings for poison used original benign code; corrected alignment now uses poisoned code. Released EHR target falls through to driving STOP, with missing EHR prompt construction; disabled rather than replaced. Released optimizer also imports unavailable driving modules and has unsafe W&B references; EHR-specific dispatch avoids these. This pilot uses ten optimization iterations and a saved-ID split, not a guessed 47-question paper subset.

The available public Drive initial listing supplied 50 authentic logs; full-corpus pagination metadata access failed twice. This incomplete memory corpus is an explicit experimental deviation. No synthetic memory records replace missing logs. Unique question IDs retain first source occurrence, with conflicts recorded; evaluation questions without reference matches remain in all-attempt companion denominators.
